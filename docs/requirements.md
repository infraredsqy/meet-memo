## 一句话

一个**常驻的会议工作台**：开会时把声音完整录下来、让人一眼看出它还活着、随叫随到问一次"刚才聊到哪儿了"；会后交给能慢慢跑的模型，做出一份说清共识与分歧的纪要。它常驻，能在不同会议之间切换，一场会就是一个目录。

## 采集与记录（R1–R17）

**R1 · 主体是"采集 + 会后处理"**：主体是录音器和会后处理；会中实时那一套是附属，出问题不影响这场会的产出——只有音频不可再生，转写可重跑、纪要可重写。

**R2 · 采集必须完整，且不能静默出事**：有几路录几路，每路独立归档、互不影响。机主原话："我不允许这个脚本中间出事儿。他要是静默退出崩溃了，那整个会议就根本没有录，那就完蛋了。"

**R3 · 录音状态必须一眼可见**：会中界面本地与远端各一块电平；电平一直有动静＝录音活着。状态要在余光里也看得出来——出事时人不会盯着屏幕。

**R4 · 采不到就要响**：采不到时弹醒目提示，可勾选在这台机器的音箱里放一声响的，离开屏幕也听得见。

**R5 · 存活判断走心跳**：界面按固定频率（1–60 秒可配）要一次心跳，要不到就弹醒目提示写明"录音已中断"。判断落在界面侧，服务只负责活着并留 log。（意图 16）

**R6 · 实时转写保留，定位是临时稿**：会中一条一直跑的实时转写，服务告警判断与会中手动总结；听错、丢段都不需要抢救，会后那份会重建一遍。

**R7 · 会中一键总结**：按一个键，十到十五秒出结果——"刚才在讲什么、讲到哪了、丢掉了什么"，几条就够；范围最短五分钟、最长整场，用户自己挑。机主原话："这个设计非常好，我非常喜欢。"

**R8 · 会后时间宽裕，换质量**：会后可以用几小时、甚至挂机到第二天早上，不为了快而牺牲质量。机主原话："我只要把机器开在那儿，我去睡觉就好了。"

**R9 · 会后拿录音整段跑离线模型，多出一条更细的稿（可选）**：离线模型（MOSSTD）整段重跑，出带说话人编号、多人场景更稳的更细的稿；当场就要纪要可跳过；它慢（一场两个半小时的会约一小时），是否比会中稿更准没有保证——两条稿是对拍关系（R11）。（意图 10）

**R10 · 说话人靠会后聚类，不要注册制声纹**：离线模型自己聚类给编号，不录样例、不建 tag、不比对（机主原话："所以这个玩意儿没有用"）。配套：不假定人数；每路各自独立编号、不跨路连身份；名字放到会后推，猜不出列出来问；名字要能改、并且记住（R30）。

**R11 · 两条转写都留，放在一起对拍**：实时稿与离线稿都保留、各写一个文件，一起给生成纪要的模型，由它按内容判断哪边可信；谁也不叫"权威"。（意图 11）

**R12 · 两条转写直接交给生成纪要的模型**：不做"先核对出一份结果、再生成纪要"的中间步骤。机主原话："你可以相信现在的 AI……你不需要先把两套转写给 AI 核对一次再生成纪要。"

**R13 · 纪要写的是共识与分歧**：说清达成了什么共识、没达成什么共识、哪里有争议。名字是一份附录，附录之外不依赖说话人身份。

**R14 · 三种场景都要成立**：

| 场景 | 录音 | 说话人 |
|---|---|---|
| 线上会议（用户本地、别人远端） | 麦克风 + loopback | 各自聚类 |
| 线下聚会（所有人同一个房间） | 麦克风 | 麦克风侧聚类 |
| 混合（几个线下 + 一个线上） | 两路都开 | 两路各自编号 |

线下是主路径，混合是实际遇到的场景；用户跑这个脚本时一定在场，不在场时叫不动他是可以接受的。

**R15 · 命令行只要两个词**：`meeting web`（起服务、开界面，开会用）、`meeting post`（只跑会后那一套，不开界面）。另有第三个动词 `meeting replay <场次目录>`：重放验证工具，拿旧录音全速重跑会后离线链（只验证、不拉纪要），守同一个命令形。

**R16 · 服务挂了必须留 log**：机主原话："你没 log，我根本就不知道之后怎么查 bug。"报警归界面，log 归服务。

**R17 · 同一时刻只录一场**：不支持同时录两场，也不为它预留结构；同时允许别的会在跑会后。

## 工作台（R18–R33）

**R18 · 一张常驻的会议工作台**：服务常驻；左边"我这些会"，右边选中的那一场；切换会议不用重启服务；同一时刻只有一场在录（R17）。（意图 2）

**R19 · 一个工作区 = 一场会 = 一个目录**：目录名就是这场会的名字，由人起——软件不生成它、不改它、不解析它（选择器里就地建的目录同样照输入的名字落盘）；日期这类语义写进目录里面的元信息。（意图 3）

**R20 · 没有默认落点**：按「新会议」＝在目录选择器（起点 `~/`）里挑：已有目录（空的当新会、有会议材料的收编、非空且没有材料的弹一句确认），或就地建一个新的、建完直接选中。列表是软件自己的一份注册表。（意图 4）

**R21 · 删除工作区只把这一场从列表移走**：文件一个字节不动，还能用"打开目录"收回来；路径不在了的那一行如实显示。（意图 5）

**R22 · 元信息是软件自己的一份记录**：字段随便加（日期、起止、分了几段，以后参会人、声音样本……）；除了 R23 那个数，一律不拿它做判据、不做校验。（意图 6）

**R23 · 一场会的长度，以实际录到的音频时长为准**：不含暂停；墙钟跨度与空档时长只当附注。（意图 7）

**R24 · 暂停就是不录内容**：那段时间不录内容（那一截写静音进文件），"暂停中"在界面上极其显眼。（意图 8）

**R25 · 一场会可以录成好几段**：手滑关掉、出去吃饭关电脑，回来能接着录同一场。段只表达"录了几次"；暂停与会中开关某一路都不切段。（意图 9）

**R26 · 结束录音之后什么都不发生**：不弹窗。工作区回到"当前没有进行中的会议"，页面上两个独立按钮：**生成会后精细稿**（走离线模型，慢，出带说话人编号的稿子）与**生成纪要**（拿手上有的稿子交给 DSH）。都不按，这一场就什么都不跑。（意图 10）

**R27 · 会后跑到哪了要看得见**：每跑完一块就落一次盘；页面上像会中转写那样往下刷，带进度条、可展开收缩；左边列表那一行一眼看得出这一场处在什么状态。（意图 12）

**R28 · 会后能打断，打断要留痕**：停掉之后状态明确写"被打断"，以后能从那一场重新按按钮跑；开着新会议时提醒一句"这会打断正在跑的会后"。（意图 13）

**R29 · 有没有会后精细稿，按钮上要看得出来**：按"出纪要"时，一眼能看出这一场有没有那条更细的稿子。（意图 11）

**R30 · 人名能改，并且记住**：界面上能把编号改成名字，改完写回纪要里那张表；"谁是谁"的表存在这一场的目录里，同一场以后再出纪要自动带上。没跑过离线聚类时，身份只有本地 / 远端两种，照样能起名字。

**R31 · 全局只留一个"显卡忙不忙"**：有一个模型开着就是忙，都关着就是闲；进度条跟着各自的工作区走。（意图 12 附注）

**R32 · 设置要能在页面上改**：一个设置按钮 → 网页内小窗 → 确定写进 config。放：换设备、告警提示音、心跳频率、快速总结默认窗口、会中切模型（多套预设）。（意图 15）

**R33 · 工具型功能按"对验证有没有用"取舍**：命令行工具类的东西，判据是它对验证有没有用；`meeting replay` 照这条落地。（意图 19）

## 不做的（用户明确排除）

- 不做 TUI：网页是唯一的界面。
- 不做注册制声纹（R10）。
- 不在会中跑离线模型：会中总结必须快。
- 不把模型或录音塞进网页：服务是本体，网页是它的一个窗口。
- 前端方案只用一条：不许会中一套、会后另一套。
- 不让会后那套挤进实时管线（R1）。
- 不假定场景与人数（R14、R10）。
- 不做全局进度条：进度跟着各自的工作区走（R31）。
- ASR 那五个参数封死：段长 / 超时 / token / 周期上限 / 覆盖率，任何节点不许改，界面上也不给入口。（意图 14）
- 不把模型留在显存里等下一次：该用的时候才拉起来，暂停、打断、跑完都当场关掉。（意图 21）
- V1 的两样东西不回来：会中的实时总结、"每 N 段 / 每 N 分钟自动总结一次"的节奏。（意图 16）

已被推翻的旧说法统一登记在 `docs/design-intent.md` 末尾的表里，这里不重复。

## 做成功是什么样

方向拿不准时拿这节照一下。他敲一条英文命令，服务和网页一起起来；开会时瞄一眼电平就知道活着，休息按一下暂停，那段时间安安静静。会后按"生成会后精细稿"就能关机去睡，醒来那一场挂着"完成"、纪要在那儿、人名想改就能改；当场要纪要就按"生成纪要"，十几分钟拿到。过几天再打开，左边排着那几场，点开就能翻纪要、两条转写和音频。整场跑下来：没有静默崩溃，没有丢掉录音，没有哪件事是他不知道的。

## 技术取向（用户确定的部分）

- Python 作为底层语言保留。
- 前端：React + TypeScript + Vite，会中与会后是同一个应用的不同视图。
- 单进程跑会议：跑会议时不需要 Node，Node 只在改界面时需要。
