# meeting · 文档路牌

> `docs/` 的入口：只做导航，正文一律在分册里，这里不存事实。每份一行「是什么 ＋ 什么时候看」；条款级引用只认稳定编号（R 号、意图条号），不认章节号。

## 项目一句话

一个**录音器加一套会后处理**：会中把声音完整录下来、让人一眼看出它还活着，会后交给能慢慢跑的模型出一份说清共识与分歧的纪要。服务是本体，界面只是它的一个窗口。

## 分册

| 文件 | 是什么 ＋ 什么时候看 |
|---|---|
| `requirements.md` | **需求锚**：R1–R33 用户要什么。拿不准取舍方向时回这里 |
| `design-intent.md` | **为什么**：21 条设计意图，每条带可推翻条件。判断一句话是不是"用户真需求"时 |
| `service.md` | **服务现状**：怎么装起、配置键正本（键与默认值、热读分档）、跑测试、能力边界。装起来用或接手改服务时 |
| `state.md` | **状态与场次**：四态与迁移、收尾与转码、快照与 `session.json`、会后与纪要产物、心跳判据、告警判定、SSE、dev 替身。接这份数据、写前端或验收脚本时 |
| `contract.md` | **双端契约**：端点表、动作信封与 `detail`、快照 schema、SSE 与重连、`settings_update`、心跳与客户端义务；golden 样本在 `contract/fixtures/`，漂移就红。写界面、写验收脚本、打这套接口或改服务对外形状时 |
| `api.md` | **指针**：HTTP 面已并入 `contract.md`，只剩去处。顺路撞到它时 |
| `backend-protocols.md` | **后端接缝**：四个协议的成员与语义、缺席档、解析入口、dev 替身、会后两层的开关。往服务里插真后端时 |
| `minutes.md` | **会后纪要生成**：吃什么输入、五个阶段、DSH 子会话怎么拉起、产物四条判据、手动子命令。想知道纪要怎么出来的、或手动跑一遍时 |
| `summary.md` | **会中总结**：窗口从哪读、四档怎么切、提示词与输出契约、端点配置、墙钟与重试、结果不进快照不落文件。想知道按一下之后发生了什么、或接手这一层时 |
| `ui-design.md` | **界面设计唯一权威**：四态、迁移、告警分级、设计 token、视觉硬门槛。做界面、定事件契约时 |
| `asr-backends.md` | **本地 ASR 选型与参数定档**：会中 / 会后各用哪套、参数为什么是这个值；值本身住在 `service.md` 与 `backend-protocols.md`。想知道这些键为什么是这个数时 |

代码与测试的路牌在仓库根 `README.md`；没实现的东西进 `.work/`，不进 docs。上手次序建议：`service.md` 起一次服务 → `state.md` 看四态与快照 → `contract.md` 学怎么打接口。
