# meeting · 会中总结

> 会中总结那一层的契约：窗口怎么切、提示词与模型输出是什么形状、端点怎么调、超时与重试的预算、动作端点的判定次序与结果口径。它是 R7「十到十五秒出结果」的现状。
>
> 内核在 `meeting/summary/`（整包只用标准库），服务接线在 `meeting/service/runtime_summary.py`。请求 / 应答 / 逐档 `detail` 的契约正文在 `docs/contract.md`。别跟会后纪要那一层混：那层在 `docs/minutes.md`。

## 1. 定位与分工

会中有人跟丢了，按一下「总结一下」，十到十五秒拿回三小段——**刚才在讲什么 / 讲到哪儿了 / 丢掉了什么**。**手动触发是唯一的触发**：这一层没有「什么时候该总结」这件事，没有任何自动节奏（`docs/design-intent.md` 第 16 条）。不注册路由、不碰快照、不写文件：转写行的 sink 喂进内存缓冲，动作端点把窗口与配置交给 `run_summary()`。

| | 会中总结（这份） | 会后纪要（`docs/minutes.md`） |
|---|---|---|
| 什么时候跑 | 人按一下，随叫随到 | 「生成纪要」按钮或 `meeting post` |
| 吃什么 | 内存里的实时转写窗口 | 盘上的两条稿子 |
| 模型怎么调 | 自己调 OpenAI 兼容端点 | 外包给一个 headless DSH 子会话 |
| 预算 | 十到十五秒（默认 deadline 25 秒） | 四小时 |
| 产物 | 几条，出现在应答体里，关掉即消失 | 一份 `meeting_final.md` 落在场次目录 |
| 落文件 | **一处都不落** | 状态文件 + 纪要 + 中间产物 |

## 2. 窗口

**读的是内存里的一条追加缓冲，不读盘**：`TranscriptBuffer` 收转写行，线程安全，`lines()` 交回副本，行数上限两万（到顶丢最老的——窗口取尾部，丢头不影响）。盘上那份 `meeting_transcript_<source>.md` 时间戳是分钟级（秒被丢掉、同一分钟会撞成一个戳），不够按时间切窗口用。

四档由用户挑，缺省 `15m`：`5m` / `15m` / `30m`（最近 5 / 15 / 30 分钟）与 `full`（整场 = 缓冲里的全部）。

**边界按行首时间戳切，不按行数切**：锚点是**缓冲末行的 `ts`**，`cutoff = 末行 ts − 窗口秒数`，从尾部向前收到 `ts < cutoff` 为止——转写停转、说话变稀时，末行比此刻早多少都不影响窗口取到那几行（拿当前墙钟当锚点会把这种缓冲切成空窗口）；同一个 `ts` 上挤着的一批行**整批一起收或一起丢**；缓冲为空才用当前墙钟兜底，交回空窗口。

**装配形状**：一行一句、原句逐字保留，`[HH:MM:SS] 正文 · 本地`——时间是那一行的墙钟时刻（模型要能说清「讲到哪儿了」），来源标在行尾（`mic` → `本地` / `loopback` → `远端`）。识别失败的占位符**原样留在里面**——它是一条信息，人正是想知道丢掉了什么，提示词负责讲清楚。

## 3. 提示词与模型输出契约

`build_messages()` 组两条消息：system 是身份说明加**七条硬规则**，user 是窗口正文加任务说明。窗口里的缺口单独有一句嘱咐：见到几个就在【丢掉什么】里写几条、说清哪一路、大概什么位置；**一个缺口都没有就写一条说明**，不许猜缺口里可能说了什么。

**输出契约**（V1 磨出来的形状照语义沿用）：

- 强制合法 JSON，形状固定 `{"bullets": [...]}`，元素是字符串，每条 bullet **以三个固定标签之一开头**（`【讲什么】` / `【讲到哪】` / `【丢掉什么】`），解析时按标签归三小段。
- **围栏容忍**：三步解析——strip、去代码围栏、正则抠第一段候选；只接受「顶层 dict、`bullets` 是 list、每个元素 strip 后非空字符串」。
- **空数组合法**：算成功（模型判断没有可讲的要点），不是失败。
- 标签只认**行首**那一处；认出的归位并去掉标签，**个别认不出不算失败**；**一条标签都认不出来算解析失败**（触发重试）。
- **重试只由解析失败触发**，第 2 次起在 messages 末尾追加一条提示；端点的四档错误**当场收工**，不再发下一次请求——同一个错误重放一遍没有意义。

## 4. 端点调用

`ModelClient` 用**标准库 `urllib.request`**，运行时不引 `httpx` / `requests`：`POST {base_url}/chat/completions`，Bearer 密钥与 JSON 两个头；请求体四格 `model` / `messages` / `temperature: 0.3` / `stream: false`，`extra_body` 非空就**原样并进去**；读 `choices[0].message.content`，thinking（`reasoning_content`）丢掉；非 2xx 优先取响应体里 `error.message` 的原文。**四档错误**：`timeout` / `bad_status` / `bad_json` / `no_content`。

`post` 是**注入点**：用例与探针都从这里进，这一层的用例一条网络请求都不发。`temp` / `model` / 密钥是**构造那一刻的快照**，中途改配置不影响已经在飞的那一次。

## 5. 配置

九个键的正本（键名、默认值与合法范围）在 `docs/service.md`。六个键启动时读一次（改了要重启）；三键热读——`summary.default_window` 与会中切模型两键 `summary.presets_json` / `summary.active_preset`。代码读不出来的口径：

- `summary.api_key` 是**可空键**，可走环境变量 `MEETING_SUMMARY_API_KEY`；没配就是没配（动作层点名缺的键，`detail.missing` 报配置键全名）。
- `summary.presets_json`：多套端点预设整装一个键（每套一个对象，`name` 必填、不重名）；**预设里的密钥不进快照、不在界面回显**。
- `summary.active_preset` 的**取值次序**：指到清单里有名有姓的那套就整套装它的；其余一切（没配、清单解析失败、名字不在清单）→ **回落平铺四键**，存量配置零迁移。预算三件套与缺省档始终走平铺键。实际用的哪套记在 `from_preset`，`missing` 据此把「这套预设缺哪一格」报成 `summary.presets_json[名字].api_key` 这样的形状。
- `extra_body_json` 用一段文本承载、不用嵌套段：配置层是「点号扁平键名的单层映射」、装载时明确拒收 dict 值；写进去的不是合法 JSON 对象时装载当场拒掉。

## 6. 预算与重试

口径是**一条墙钟 deadline**（`summary.deadline_seconds`，默认 25 秒）：

- `deadline = 开始时刻 + deadline_seconds`；**每一次请求的超时取「当时的剩余预算」**（25 → 15 → 5 递减），剩余不足 0.05 秒就不再发下一次请求。
- `max_attempts`（默认 3）只是**上限**，预算用尽即停。
- 停下来时**如实报数**：`elapsed_seconds` 与 `attempts` 在成功与失败两条路上都填。

**三种收场**：成功（`ok=true`，`bullets` / `what` / `where` / `lost` 都填上，`unlabeled` 记漏标签条数）；窗口里一行都没有（`ok=true`，三段空、一个模型请求都不发）；失败（`ok=false`，`error` 人话 + `detail` 机器可读）。**配置缺键挡在出门前**：三个端点键缺一个就当场收工，**一个请求都不发**。

## 7. 动作与记录端点

动作 `summarize` 的**判定次序是固定的**：判态 → 校验 `window` → 看转写健康 → 看模型端点配置 → 才动手；前面几档没过时**一个模型请求都不发、一条记录都不写**。`window` 取值非法当场回 `invalid_setting`(400)，**不静默落缺省档**。请求与成功体、逐档 `code` / `detail` 的正文见 `docs/contract.md`。

**一次模型调用跑在工作线程上**（专用线程池提交 + 墙钟 deadline 的 `asyncio.wait_for`）：25 秒的等待不许按住 `/api/state`、三个 SSE 通道与心跳节拍——到点放弃的是**等待**，已经交出去的那次调用照跑到底。服务侧**不做闸、不排队**：两个页面同时按下就是两次独立的总结，各自记一条；界面自己按「进行中」把按钮禁掉。

**本场总结记录** `GET /api/summaries`：任何状态下都 `200`，应答体 `{session_id, entries}`；只记**成功产出**的那几次、按时间先后，记录那一条比动作成功体少一格 `lines`；没有场次或一次都没按过时 `session_id` 为 `null`、`entries` 空数组。

## 8. 结果不进快照、不落文件

**结果是一过性的视图产物**，口径落在三处：

- 走 `summarize` 动作的**应答体**，记录走 `GET /api/summaries` 的内存表，**不加 SSE 事件**；
- **不进快照**：快照是**会议的**权威状态——打一次总结前后各取一次 `/api/state`，`revision` 与顶层九键逐字相同（前端契约层用两道硬门钉住它）；
- **不落任何文件**：记录活在内存里、会话级——新的一场 `start` 把缓冲与记录**一起**清空，服务关停同样清掉。
