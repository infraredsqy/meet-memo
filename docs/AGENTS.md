# docs/ —— 现状与判据的正本：这个项目现在是什么

> 本文件是路牌，上限 20 行：一行一份，只说什么在这里、什么时候看。
> 动手之前先读 `rules.md`（测试 / 文档 / 注释三条纪律）与 `design-intent.md`（这个项目的思路与理念）。

- `rules.md` —— **法**：测试、文档、代码注释三条纪律。动手之前看
- `design-intent.md` —— **为什么**：设计意图逐条，每条带可推翻条件。判断一句话算不算真需求时看
- `requirements.md` —— **需求锚**：用户要什么，R 号是稳定引用。拿不准取舍方向时看
- `service.md` —— **服务现状**：怎么装起、命令面、配置键与默认值（正本）、log、退出码、跑测试。装起来用、或接手改服务时看
- `state.md` —— **状态与盘上产物**：四态与收尾、快照、场次目录与会后产物、心跳、告警、SSE、dev 替身。接这份数据、写界面或验收脚本时看
- `contract.md` —— **双端契约**：端点、动作信封与 `code`/`detail`、快照 schema、SSE 与重连、客户端义务。打这套接口或改服务对外形状时看
- `backend-protocols.md` —— **后端接缝**：四个协议的成员与语义、缺席档、解析与注入。往服务里插真后端时看
- `minutes.md` —— **会后纪要**：吃什么、经哪几步、怎么拉起 DSH、产物判据。想知道纪要怎么出来时看
- `summary.md` —— **会中总结**：窗口、提示词与输出契约、预算与重试。想知道按一下之后发生了什么时看
- `ui-design.md` —— **界面口径正本**：信息架构、交互清单、设计 token、视觉硬门槛。做界面时看
- `asr-backends.md` —— **模型选型与参数依据**：会中 / 会后各用哪套、为什么是这些值。想知道那些默认值凭什么时看

可机读的契约基准不在这里，在 `contract/README.md`。
