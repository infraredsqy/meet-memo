## 3. 设备与环境坑（C2 / C3）

V1 在真实机器上撞出来的坑，谁重写采集谁就会原样再撞一遍：

| # | 坑 | 结论 |
|---|---|---|
| C2 | COM 未初始化 | soundcard 在**子线程**里必须手动 `CoInitializeEx`，否则报 `0x800401F0`，而这个失败会被 `except: pass` 吞掉，只能从"采到的是全零"倒推 |
| C3 | USB 声卡多个 host API 端点行为不同 | 同一块 USB 声卡暴露多个同名端点：WASAPI 只支持 48k、DirectSound 能开 16k 但返回全零（静默失败）、只有 MME 能正常 16k；试开顺序 WASAPI→DirectSound→MME、取第一个可用 |

## 4. transformers 与测试配置的陷阱（C8 / C9；E8 / E9 是同一件事的文档侧记法）

| # | 坑 | 结论 |
|---|---|---|
| C8 | transformers 5.x 自定义 `logits_processor` 的签名陷阱 | 自定义 processor **只能声明 `(self, input_ids, scores)`**；写成 `*args, **kwargs` 在 generate 内部抛 `ValueError`，堆栈指向 transformers，很容易误判成"模型不支持这个参数" |
| C9 | 测试里 monkeypatch config 的函数不管用 | `from ... import f` 绑的是**函数对象**，测试会一边"通过"一边什么都没验；要验就得写 `config.json`（走 `save_asr_tunables()`） |

## 5. 导入顺序约束（C10）

先 `import transformers`、再 `import speechbrain`；反过来 speechbrain 会抢做依赖探测，出现难定位的版本不匹配。条文正本在 `docs/backend-protocols.md` 的「导入顺序」。

## 6. 占位符为什么不能带 `**名字**:`（E12）

占位符契约的本体在 B12。跨组件的原因：占位符若带 `**名字**:`，下游会把 `**X**:` 当说话人标签；原始消费者就是 A7 那条解析正则。

## 7. 会中总结：沿用的语义与三条纪律（B15、纪律 14 / 15 / 16）

**B15 · 从 V1 沿用的总结器语义**

- 频率门控（每 N 段 / 每 N 秒一档、关闭档）**留在 V1 没搬**——V2 只有手动按钮（R7）。
- prompt 组装：每次注入完整的累积转写窗口；强制 `{"bullets":[...]}`、容忍 ```` ```json ```` 围栏、合法空数组不算失败、失败重试 3 次——V1 拿真实会议磨出来的形状。
- ⚠️ **V1 没有任何时间窗口切片**：R7 要的「最短五分钟、最长整场」是 V2 自己实现的。

**纪律 14 · ASR 五参数封死**：段长 / 超时 / token / 周期上限 / 覆盖率，任何节点不许改，界面不给入口（见 `docs/requirements.md` 的"不做的"）。这套值的作用之一是防 ASR 自己爆掉（B4）；只有机主本人明确要求调它时才可动。

**纪律 15 · 参数档位不从零标一遍**：V1 探针量出的标定值（B1 / B2 那组）在 V2 直接沿用；V2 只为自己**新写**的部分定值（总结窗口四档、deadline、尝试上限）。从零再标，最好白花时间得到同一组数，最坏在更差的观测条件下试出更松的值。

**纪律 16 · 不许花机主的 token**：打模型端点是真金白银。用例与探针一律注入假件、不打真实端点（`meeting/summary/client.py` 留 `post` 注入点，`tests/conftest.py` 另有 autouse 兜底）；真实端点与真实素材的验证写成一次性 `.work` 脚本、跑完封存证据、不进 `tests/`；`tests/` 要便宜且确定——单条用例 ≤5 秒、单个测试文件 ≤10 秒，重依赖的走 `slow` 分档（见 `docs/service.md`）。

## 8. 被继承的流水线语义（R2 / R3）

这两格的**结构**（V1 那套多线程流水线形态）是 V2 明确扔掉的，被继承的是**语义**：

- **R2 ①「时间戳必须在入队时打」**：旧实现等 ASR 返回才取时间戳，一个退化段卡住几分钟，后面所有积压段全被盖上"解卡那一刻"的时间。V1 后期已改掉 → V2 直接继承"入队即盖采集时刻"，别再当成现存缺陷去重写一遍。
- **R2 ②「不丢内容、禁止 busy-drop」**：队列无界、单 worker 顺序消费，任一段都不因"忙不过来"被丢掉。
- **R3「采集路径与模型路径解耦到『模型停摆不影响落盘』」**：V1 事故里唯一没丢的就是音频本身，丢的是时间戳与产出。V2 把这条**显式做成结构**（采集一路、模型一路，谁也不等谁），把 V1 那种"恰好没耦合上"的运气换成写进设计里的硬约束。

## 9. 两条操作纪律（纪律 9 / 纪律 11）

**纪律 9 · 搬运时的测试覆盖空洞**：V1 的 `_DeadlineStop`、`_is_noise_segment`、离线切段三块**零测试覆盖**——搬这些时 V1 的用例不会给你任何提示，改错搬漏都不报警，只能自己补测试。可照搬的做法：把真实故障的两行循环样本内联成永久回归基线。

**纪律 11 · 每个数字都要带口径，口径不同的数字不得混在一句话里比较。** 交付物正文里的数值都必须能用某类命令复算；同一段音频按整秒判定与按样本判定会得出两个都"对"的数，混着说两个都不成立。测"数字静音"要用解码后**逐样本**判定，不要用聚合值当判据。
